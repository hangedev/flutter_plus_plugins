### sensors_plus-7.0.0-ohos-1.0.1

### Fixed

* Consistency
The incomplete OHOS entry API contract is the core issue. In lib/src/sensors_ohos.dart, the Sensors class overrides only 4 sensor methods, missing barometerEventStream(), causing Sensors().barometerEventStream() to fall back to the base class and throw UnimplementedError — the barometer feature is actually unavailable on OHOS, even though the native layer SensorsPlusOhosPlugin.ets already implements BAROMETER support, creating an inconsistency between the Dart layer and native layer capabilities. At the same time, lib/sensors_plus_ohos.dart only exports 4 deprecated getters at the top level, missing barometerEvents and all 5 *EventStream() functions, and the deprecated getters lack @Deprecated annotations, inconsistent with the main entry sensors_plus.dart behavior, preventing users from accessing the barometer through the standard entry point. The fix is to complete the Sensors class overrides, supplement all functional API entries for OHOS, and add @Deprecated annotations to the deprecated getters. Additionally, the Snake game previously adapted x/y swapping due to assumptions about the OHOS accelerometer coordinate system, but after confirmation those assumptions were invalid, the adaptation has been fully reverted to maintain behavior consistent with upstream. The stopSensor fix also unified the semantics of "update state only on success," consistent with startSensor.

* Memory Leaks
Incomplete plugin lifecycle cleanup is the primary leak risk. onDetachedFromEngine originally only cleared the MethodChannel handler, without cleaning up the 5 EventChannels, canceling sensor listeners, or nulling all references, hindering GC. After the fix, a complete three-step cleanup is performed: call onCancel individually to cancel sensors, call setStreamHandler(null) individually to clean up EventChannels, and null out all handler and channel references. The issue where the MethodChannel reference was not nulled in onDetachedFromEngine has also been fixed. The plugin did not implement the AbilityAware interface, missing onAttachedToAbility and onDetachedFromAbility (-8/-15 points deducted), preventing sensor resource release after Ability destruction and potentially leaking UIAbility references. This interface has now been implemented: onAttachedToAbility saves the binding, and onDetachedFromAbility stops all sensor listeners and clears references. The Snake dispose order was incorrect — super.dispose() was called before canceling timers and stream subscriptions, violating Flutter lifecycle constraints. This has been fixed to clean up resources first before calling super.dispose().

* Documentation Quality
The two README files (English and Chinese versions) contain multiple discrepancies from the code. The dependency ref branch name is incorrect (br_sensors_plus-v7.0.0_ohos versus the actual _dev branch — following the documentation would directly fail); the TAG version is written as beta.2 but only beta.1 exists; the TAG version mapping table branch name is incorrectly written as br_battery_plus-v7.0.0_ohos; the example path ohos/example/lib/main.dart does not exist; the Barometer property table title is copied from MagnetometerEvent Filters; the 4 event property tables are missing the timestamp field; the license type is written as BSD-3-Clause with a link to the non-existent ohos/LICENSE (the actual license is MIT and located at the package root); sections §5/§6 are empty. Following the documentation quality review report, interface description accuracy has been further fixed: the API table Input column has been changed from / to the actual parameter samplingPeriod: Duration, with a parameter description table added, SensorInterval constant table, sample call code, OHOS project configuration steps, Sensors singleton class description, deprecated API comparison table and migration recommendations, and [OHOS]-specific comments added to sample code (broadcast stream characteristics, sampling period impact, permission requirements, onError handling).

* Test Coverage
This is the dimension with the most points deducted, with both test coverage and Demo coverage at only 50% (14 public interfaces uncovered, triggering a one-vote veto). The gaps are concentrated in: the Sensors() constructor and 5 *EventStream() methods with no direct tests, 4 deprecated top-level properties with no tests, userAccelerometerEvents for the OHOS entry with no tests at all, SensorInterval's three constants with no tests, and overall missing exception scenarios, edge cases, and concurrency scenarios. After fixes: test/sensors_test.dart expanded from 5 test cases to 43, test/sensors_plus_ohos_test.dart expanded to 38, covering all interfaces, constants, deprecated APIs, error propagation, sampling period boundaries, and concurrent subscriptions; barometerEvents (unique to the OHOS entry, originally 0% coverage) now has unit test cases and a demo demonstration added. A new example/lib/sensors_coverage_demo.dart has been created to exercise all public interfaces in the background (without displaying UI), called from main.dart's initState. The example's widget_test.dart, originally an invalid template test (looking for the non-existent "Running on:" text), has been rewritten with 4 test cases matching the actual UI, and Timer remnants from sensor streams that caused test failures have been resolved.

* Stability
This is the most severe dimension with the most points deducted, with issues concentrated entirely in the ArkTS native layer. The event subscription cancellation chain is broken: onCancel was originally an empty implementation, and the 5 sensor.on() callbacks were never canceled, continuously consuming CPU/battery. The exception propagation chain is broken: onMethodCall calls neither result.success() nor result.error(), causing Flutter-side Futures to never complete and potentially freezing the UI; sensor.on() failures only log without propagating to Flutter. Resource release is incomplete (see Memory Leaks dimension). Duplicate callback registration: sensor.on() can be executed repeatedly even when the interval hasn't changed, causing duplicate events to be sent to Flutter. sensorId is declared optional but switch has no default branch to handle undefined. systemDateTime call exceptions are only logged without propagation. currentInterval is updated before sensor.on() succeeds, leaving state inconsistent on failure. onMethodCall has no overall try-catch, so any exception causes result to never return. The 5 sensor data callbacks lack try-catch, and delayed callbacks after event has been nulled can cause crashes. stopSensor() unconditionally sets isListening = false even on failure, making state inconsistent with actual listening, causing subsequent startSensor() to skip cancellation and directly re-register. sensor.off() error propagation chain is broken. Fixes: onCancel now calls stopSensor() and clears events; onMethodCall has an overall try-catch ensuring result is always called; the 5 send*Event methods each have try-catch added; stopSensor() now returns a boolean and only sets isListening = false on success, with startSensor() skipping re-registration on failure; onListen previously attempted to use sensor.hasSensor() for availability pre-checking, but this API is not supported in the current HarmonyOS SDK (causing compilation errors) and has been removed, replaced by startSensor's internal try-catch that notifies Flutter via event.error('UNAVAILABLE') on subscription failure, equivalent to Android's NO_SENSOR behavior.
